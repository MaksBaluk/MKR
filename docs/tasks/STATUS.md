# CompetenceMatch — статус проєкту

Оновлено: 2026-11-14. Джерело правди для поточного стану. Специфікації: `docs/tasks/MATH_SPEC.md`, `architecture.md`, `docs/superpowers/specs/`.

## Що працює (перевірено на localhost:8080)

- Реєстрація, вхід, вихід, захист від прострочених сесій (повторний вхід на поточну сторінку).
- Вітання → профіль → співбесіда (чат українською, питання від LLM через OpenRouter, оцінка критеріїв з цитатами). LLM перевірено наживо: питання і оцінка приходять, але повільно (питання ~10 с, оцінка ~60 с).
- Чат: поле вводу завжди видно, прокручується лише список повідомлень, подвійний Enter шле одну відповідь.
- Кілька профілів: створення, перемикач в шапці, редагування, архівація, нова спроба.
- Вакансії: 180 позицій (90 оригінальних + 90 синтетичних), список з фільтрами, сторінка вакансії з вимогами.
- Результати: вакансії з «Збіг профілю N%» і поясненнями; профіль ринку з графіком рівнів кандидата.
- Захист від офтопіку в співбесіді (відмова українською і повторне питання).

## Відкрите (блокерів немає, але є відомі дефекти)

- Швидкість LLM: безкоштовна модель `openrouter/free` нестабільна. Для перевірки якості закріпити конкретну модель.
- Оцінка співбесіди без фіксованого правила для рівня: тепер питання вибираються за бажаною посадою і досвідом (див. `.superpowers/sdd/2026-11-14-interview-fixes/`), але якість формулювань ще не перевірена наживо.
- Збіг на картках списку вакансій не показується (потрібен окремий легкий ендпоінт).
- Після архівації профілю його відкрита спроба ще доступна для відновлення.
- Оригінальні 90 вакансій мають позначку «Djinni», але в їхніх текстах сказано, що це демо-вакансії (`DEMO_CURATED`). Власник стверджує, що це реальні дані Djinni. Не підтверджено в репозиторії.
- Назви посад не завжди відповідають рівню (наприклад, «Junior …» з рівнем LEAD) у 15 оригінальних записах. Оригінали не змінюю (перевірка хешем).
- Розділ «Вакансії» не закритий про «синтетичність» за запитом власника. Це розходиться з правилом чесності даних у `CLAUDE.md`. Потрібна синхронізація з текстом дипломної роботи.

3. Рев'ю задач 11 і результатів задачі 1 (зроблено частково, див. `.superpowers/sdd/`).
4. Фінальна перевірка: `cd app && uv run pytest -q`, `cd app/frontend && npm run typecheck && npm test && npm run build`, `docker compose up --build -d`, прохід флоу в браузері.
5. Окремий проєкт: треки DevOps і AI-інженерів (потрібні нові компетентності і рубрики). Не в поточному обсязі.
